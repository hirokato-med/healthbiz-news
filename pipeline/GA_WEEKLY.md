# 週次レポートの準備（Google アナリティクスとの接続）

毎週月曜の朝、`pipeline/ga-weekly.mjs` が Google アナリティクス 4（GA4）から前の1週間の数字を取り、
「利用者・よく読まれた記事・タブ別の閲覧・ボタン・役に立った・気づき」をまとめたメールを送ります。
そのために、Google 側で「プログラムが数字を読みに行くための鍵」を1回だけ作ります。所要時間は 15 分ほど。

必要なのは次の2つの値です。作り方を順に書きます。

| 名前 | 中身 | 例 |
|---|---|---|
| `GA_PROPERTY_ID` | GA4 の **プロパティ ID**（9桁ほどの数字） | `123456789` |
| `GA_SERVICE_ACCOUNT_JSON` | サービスアカウントの **JSON キー** の中身（まるごと） | `{ "type": "service_account", … }` |

> 「測定 ID」（`G-PYC7DZRBKW`）とは別のものです。測定 ID はアプリが数字を**送る**ための ID、プロパティ ID は数字を**読む**ための ID です。

## A. Google Cloud で鍵を作る（手順 1〜8）

1. ブラウザで https://console.cloud.google.com/ を開き、**GA4 を管理している Google アカウント**でログインします。
2. 画面上部のプロジェクト名（または「プロジェクトを選択」）をクリック → 右上の **「新しいプロジェクト」** → プロジェクト名に `hb-news-report` と入れて **「作成」**。作成後、上部のプロジェクト名がそれに切り替わっていることを確認します。
3. 左上の **≡（ナビゲーション メニュー）** → **「API とサービス」** → **「ライブラリ」**。
4. 検索窓に `Google Analytics Data API` と入れ、出てきた **「Google Analytics Data API」** を開いて **「有効にする」**。（「Google Analytics Admin API」や「Google Analytics API」という似た名前のものではありません）
5. ≡ → **「IAM と管理」** → **「サービス アカウント」** → 上の **「+ サービス アカウントを作成」**。
6. サービスアカウント名に `hb-news-weekly` と入れて **「作成して続行」** → ロールは何も選ばず **「続行」** → **「完了」**。
7. 一覧に `hb-news-weekly@hb-news-report….iam.gserviceaccount.com` のような **メールアドレス** が出ます。これをコピーしておきます（手順 10 で使います）。
8. そのサービスアカウントをクリック → 上のタブ **「キー」** → **「鍵を追加」** → **「新しい鍵を作成」** → キーのタイプ **「JSON」** → **「作成」**。JSON ファイルが1つダウンロードされます。
   - **このファイルは秘密です。** メールや Slack で送らない、リポジトリに入れない。使い終わったらパソコンから消してよいです（手順 13 で中身を登録したあと）。

## B. GA4 でそのアカウントに閲覧を許可する（手順 9〜11）

9. https://analytics.google.com/ を開き、左下の歯車 **「管理」** をクリック。
10. 「プロパティ」の列にある **「プロパティのアクセス管理」** → 右上の **「+」** → **「ユーザーを追加」**。
    - メールアドレスに手順 7 でコピーした **サービスアカウントのメール** を貼る
    - 「新しいユーザーにメールで通知する」の **チェックは外す**（相手は人ではないので）
    - 役割は **「閲覧者」** を選ぶ（それ以上は不要）
    - **「追加」**
11. 同じ「管理」画面の「プロパティ」の列で **「プロパティの詳細」** を開き、右上に出ている **「プロパティ ID」**（数字だけ）をメモします。これが `GA_PROPERTY_ID` です。
    - 同じ画面の **「レポートのタイムゾーン」** が **「日本」** になっていることも確認してください（週の区切りがずれないように）。

## C. Claude に渡す（手順 12〜13）

12. Claude のクラウド環境（この配信を動かしている環境）の設定で、**環境変数（シークレット）** を2つ追加します。
    - 名前 `GA_PROPERTY_ID`、値は手順 11 の数字（例 `123456789`）
    - 名前 `GA_SERVICE_ACCOUNT_JSON`、値は手順 8 の JSON ファイルを**テキストエディタで開いて中身を全部コピー**したもの（`{` で始まり `}` で終わる、改行を含めてそのまま）
13. 登録できたら、Claude に「週次レポートを試しに出して」と頼んでください（内部では `node pipeline/ga-weekly.mjs` を実行します）。レポートの文面が返ってくれば完了です。
    - エラーが出たら、下の「困ったとき」を見てください。

## D. 記事名やボタン名まで出すために（手順 14〜15、できれば）

GA4 は「記事タイトル」「ボタンの種類」のような**アプリ独自の項目**を、登録しないと集計してくれません。
登録しないままでもレポートは出ますが（記事ランキングは記事ページの表示回数で代用、ボタンは合計だけ）、次を登録すると内訳が出ます。

14. 「管理」→「プロパティ」の列の **「データの表示」** → **「カスタム定義」** → **「カスタム ディメンションを作成」**。
15. 次の5つを、1つずつ作ります。範囲はすべて **「イベント」**、ディメンション名と「イベント パラメータ」には同じ文字を入れます。
    - `article_title`（記事タイトル）
    - `category`（記事のカテゴリ）
    - `kind`（ボタンの種類）
    - `reaction`（役に立った の反応）
    - `channel`（見ていたタブ）
    - 登録した時点から集計が始まります（過去にさかのぼっては出ません）。登録後、数字が出るまで1〜2日かかります。

## 毎週の実行について

- レポートは **直近7日（昨日まで）** と **その前の7日** を比べます。GA4 への反映は1〜2日遅れることがあるので、日曜の分は少なめに出ることがあります。
- 手で出したいときは `node pipeline/ga-weekly.mjs`。数字だけ欲しいときは `node pipeline/ga-weekly.mjs --json`、期間を変えるときは `--days 14`。

## 困ったとき

| 画面に出る言葉 | 原因と直し方 |
|---|---|
| `環境変数が足りません` | 手順 12 の2つが登録されていない、または名前の綴りが違う。 |
| `GA_PROPERTY_ID は数字だけです` | 測定 ID（`G-…`）を入れている。手順 11 のプロパティ ID（数字）に替える。 |
| `invalid_grant` / `Invalid JWT Signature` | JSON キーの貼り付けが欠けている。手順 8 からやり直して、中身を全部貼り直す。 |
| `invalid_grant` / `account not found` | サービスアカウントが削除されたか、別プロジェクトのキー。手順 5〜8 をやり直す。 |
| `HTTP 403` / `PERMISSION_DENIED` | 手順 10 の「閲覧者」が付いていない。メールアドレスの貼り間違いが多い。 |
| `HTTP 403` / `has not been used` / `SERVICE_DISABLED` | 手順 4 の API が有効になっていない。有効にして数分待つ。 |
| `HTTP 404` / `property` | プロパティ ID が違う。手順 11 を確認。 |
| 「カスタムディメンション … が登録されていない」という注記 | エラーではありません。手順 14〜15 を行うと内訳が出るようになります。 |

鍵を作り直したときは、`GA_SERVICE_ACCOUNT_JSON` も新しい中身に差し替えてください。古い鍵は Google Cloud の「キー」タブから削除できます。
