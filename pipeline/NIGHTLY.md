# 配信手順（毎日 12時・18時・22時）

このファイルは、配信を担当する Claude セッションが最初に読む手順書。1日3回（12時・18時・22時）配信する。

**配信時刻から逆算して動く。** 定期実行は各配信時刻の 35 分前（11:25 / 17:25 / 21:25 JST）に始まる。
目標は **配信時刻（12:00 / 18:00 / 22:00）までに push を終える** こと。調査に時間がかかりそうな候補は無理に追わず、次の回に回す。
配信時刻を過ぎそうなときは、本数を減らしてでも時刻を優先する（厚く書く1本だけでもよい）。
人が読んでも手順がわかるように書いてある。文体は `COMMENT_STYLE.md`。

## ゴール

前回の配信以降に出た PR TIMES と適時開示（TDnet）から **ヘルスケアビジネスのニュースを 1〜3本** 選び、
要約と **加藤浩晃のコメント** を付けて `data/articles.json` に追加し、GitHub に push する。
アプリは push された JSON を読むので、push が完了した時点で配信完了。

**無理に本数を揃えない。** 午前の回や土日はリリースが少ないので1本、0本の回があってもよい（1日合計で5本前後が目安）。
0本の回は記事を push せず、その旨を報告して終了する（Substack の更新だけは行う）。

## 手順

### 0. 準備
- リポジトリ `hirokato-med/healthbiz-news` を clone（既存の clone があれば `git pull origin main`）。
- `data/articles.json` を読み、**配信済みの source_url と前回の配信日** を把握する。
- 今日の日付（JST）を `YYYY-MM-DD` で確定する。

### 1. 収集
PR TIMES を **2つの検索** で見る。両方の結果を合わせ、重複を除く。

```bash
node pipeline/prtimes.mjs 医療 ヘルスケア > /tmp/list.json
```

**上場企業の動きは PR TIMES に出ないことが多い。** 必ず TDnet（適時開示）も見る:

```bash
node pipeline/tdnet.mjs            # 今日のヘルスケア関連の適時開示（表題で絞り込み済み）
node pipeline/tdnet.mjs 2026-10-20 # 前日分（前回配信以降に出たもの）
```

適時開示の PDF は `curl -sSL <pdf> -o x.pdf && pdftotext -layout x.pdf -` で読む。
提携・買収・薬事承認・FDA 対応・業績修正など、事業に直結するものを候補に入れる。

**海外のヘルステック企業の動きも見る**（PR Newswire ヘルスケア、Fierce Healthcare、MedCity News、STAT News）:

```bash
node pipeline/overseas.mjs 2026-10-21T09:00:00Z > /tmp/overseas.json   # 前回配信の updated_at 以降
```

海外は **1日1本を目安（1回あたり最大1本）**。拾うのは、海外ヘルステック企業の大型資金調達（5,000万ドル以上が目安）、注目度の高い FDA 承認・クリアランス（デジタルヘルス・機器）、大手テック（Apple / Google / Amazon / Microsoft / OpenAI / Samsung など）の医療分野の動き、M&A、大手保険・病院チェーン・製薬の事業の動き、日本市場に示唆のあるもの。
落とすのは、米国内の制度の細かい話、人事、決算日程の告知、訴訟・株主向け通知、イベント告知。
ニュースサイト（Fierce / MedCity / STAT）で見つけた件は、**必ず当事者のプレスリリース（企業サイト・PR Newswire・Business Wire）を探して読み、それを `source_url` にする。** STAT+ など有料記事は見出しだけで書かない。

（スクリプトが使えない場合は、次の2つのページを取得して記事リンクを拾う）
- 医療: https://prtimes.jp/main/action.php?run=html&page=searchkey&search_word=%E5%8C%BB%E7%99%82
- ヘルスケア: https://prtimes.jp/main/action.php?run=html&page=searchkey&search_word=%E3%83%98%E3%83%AB%E3%82%B9%E3%82%B1%E3%82%A2

拾う範囲は **前回の配信（`data/articles.json` の `updated_at`）から今まで** に出たもの。前回の配信が無ければ当日0時以降。
実行時刻の直前（30分以内）に出たリリースは翌日分に回してよい。
一覧の日時は相対表記（「3時間前」）で潰れていることがあるので、候補に残したものは記事ページで正確な日時を確認する。

### 2. 絞り込み（1回あたり上限3本）

**拾うもの**
- 資金調達、薬事承認・保険適用、企業間の提携・M&A・事業譲渡
- 制度や政策の動き
- 大企業やスタートアップの新規事業、医療機関との連携
- 臨床研究の結果公表
- ピッチコンテストやアクセラレーターの受賞・採択（ICCサミット、IVS、東京都ASACなど）
- 海外の重要な動き

**落とすもの**
- 大学の受賞・イベント・講座・オープンキャンパス告知（特に岡山大学が大量に配信するので機械的に外してよい。ピッチコンテストの受賞とは区別する）
- 個別クリニックや歯科医院の宣伝・用語解説
- アンケート調査だけの PR
- 医療と無関係なもの
- すでに `data/articles.json` にある source_url

カテゴリは次の9つから1つ: `device`（医療機器）/ `wearable`（ウェアラブル）/ `drug`（製薬・創薬・OTC）/ `digital`（デジタルヘルス: 患者・生活者向けのデジタルサービス。SaMD・DTx・オンライン診療・健康アプリ・PHR・医療相談）/ `dx`（医療DX: 医療機関・薬局・介護事業者の業務のデジタル化。電子カルテ・レセプト・記録AI・院内の生成AI・医療情報基盤・医療データ利活用・セキュリティ・患者コミュニケーションのシステム）/ `service`（ヘルスケアサービス・保険・健康経営・美容）/ `longevity`（ロンジェビティ: 健康寿命・老化研究・予防・フレイル・高齢者の健康行動、美容医療のうちエイジング文脈のもの）/ `policy`（政策・規制）/ `global`（海外: 海外の企業・機関が主語のニュースは、分野にかかわらずこれ。日本企業の海外展開は国内の分類のまま）。

### 3. 調べる
- **いちばん重要な1本を先に決める。** この1本だけ厚く書く。その回の記事がその1本だけでもよい。
- **トップ記事（`featured`）は「直近24時間でいちばん大事な1本」。** 新しい順ではない。`data/articles.json` で今 `featured: true` になっている記事（前の回のトップ）と、今回の厚い1本を比べる:
  - 今回の1本のほうが大事なら `featured: true` を付ける（publish.mjs が前のトップを自動で外す）。
  - 前のトップのほうが大事なら、今回は全記事 `featured: false` のままにする（前のトップが残る）。
  - 判断の目安: 業界の構造が動く話（上場企業の M&A・事業売却、制度変更、薬事承認、大型の資金調達）＞ 大企業の新規事業・提携 ＞ スタートアップの新サービス。金額と当事者の規模が大きいほど上。
  - 加藤さんがチャットで「これをトップに」と言った場合は `node pipeline/feature.mjs <source_url>` で差し替える。
  - **トップ記事には必ず画像（`image_url`）を付ける。** トップは画像を大きく出す枠なので、画像が無い記事はトップにしない。
    - いちばん大事なニュースに画像が無いとき（適時開示や官公庁の発表など）は、**当事者のロゴでよい。** 次の順で探して `image_url` に入れる:
      1. 自社サイトの同じ件のページや製品ページの og:image（`node pipeline/ogimage.mjs <url>`）
      2. 自社サイトのトップページの og:image（たいていロゴ。`node pipeline/ogimage.mjs https://www.example.co.jp/`）
      3. 発表元が官公庁なら、その官公庁のロゴ（下の表）
    - 配信後に付けるときは `node pipeline/setimage.mjs <source_url> <画像URL>`。
    - **トップ以外の記事も、画像が無ければ同じ方法でロゴを付ける**（一覧のサムネイルが揃う）。
    - それでも画像が無ければ、その記事は `featured: false` のまま通常の行に出し、画像のある記事の中でいちばん大事なものをトップにする。

  官公庁などのロゴ（各サイトの og:image。表示が崩れたら `ogimage.mjs` で取り直す）:

  | 発表元 | 画像 URL |
  |---|---|
  | 厚生労働省 | https://www.mhlw.go.jp/common/img/img_ogp.jpg |
  | PMDA | https://www.pmda.go.jp/files/000253405.png |
  | デジタル庁 | https://www.digital.go.jp/themes/custom/gov_theme_da_2023/assets/images/ogp.png |
  | 内閣府 | https://www.cao.go.jp/common4/img/ogp_image001.jpg |
  | 東京都 | https://www.metro.tokyo.lg.jp/documents/158990/5052145/opg.png/3c79ba89-ab16-4589-4fad-b5b411615b25?version=1.1&t=1764164520819&imagePreview=1 |
  | 日本取引所グループ（JPX） | https://www.jpx.co.jp/common/images/other/nlsgeu000000pud7-img/ogp.png |
  | FDA | https://www.fda.gov/themes/custom/preview/img/FDA-Social-Graphic.png |
  | 経済産業省 | og:image 無し。`https://www.meti.go.jp/` 内のロゴ画像を探す |
- その1本は記事本文まで読む: `node pipeline/release.mjs <url>`（本文・公開日時・og:image・会社概要を JSON で返す）。事業内容、解決しようとしている課題、金額と相手、資金使途、実績の数字を押さえる。両社がリリースを出している案件は両方読み、URL も両方載せる（`source_url_2`）。
- **上場企業が当事者のときは、その会社の自社サイトのニュース／IR ページまで見に行く。**
  - 同じ件の自社リリース・適時開示があれば読み、URL を `source_url_2` に載せる（PR TIMES と両方）。
  - IR の業績（直近の通期売上・営業利益、業績予想）を押さえ、「この会社にとってどの規模の話か」をコメントに入れる。IR ページが JavaScript でしか表示されない場合は、ブラウザで開いて読む。
  - 上場企業には、代表者なしの軽い `company` ブロックを付ける: `{ name, listed: "東証プライム" のような市場, financials: "2026年3月期 売上647億円、営業利益…。今期予想…"（1〜2文）, profile: 事業内容を1文, url: 会社サイト }`。アプリの企業ページ（記事の社名をタップ）に出る。
- 取り上げた会社のうち **未上場で知名度が高くない会社** は、リリース下部の会社概要を読み、代表者名でウェブ検索して経歴を調べる（`company` に入れる）。
  - 上場企業（東証プライム・スタンダード・グロース）には代表者の経歴は付けず、上記の軽いブロックにする。上場企業が主語で相手方が未上場のときは、相手方に通常のブロックを付ける。
  - **代表者が医療者かどうかを必ず確認する。** 医師・歯科医師・薬剤師・看護師などと確認できたら経歴の冒頭に「医師。」のように入れる。確認できなければ資格について一切書かない（「不明」とも書かない）。経歴自体が取れないときは `ceo` を `{ name, bio: "" }` のように bio を空にする（アプリは名前だけ出す）。推測で埋めない。

### 4. 書く
各記事:
- **title**: 「社名、サービス名が〜した」の形で、**どこが何をしたかが見出しだけでわかる**ように。50字前後、長くなっても見出しで完結させる。社名を入れるのは事業の当事者のときだけ（配信元がイベント会社・PR代行・持株会社なら、事業の主体から書き出す）。数字が入るなら入れる。
- **summary**: 要点を **3つ**、各1文（40〜70字）。リリースの事実だけ（金額、相手、日付、数字）。
- **comment**: `COMMENT_STYLE.md` の文体。**厚く書く1本は 250〜350字**、残りは **60〜150字（1〜4文）**。全部同じ熱量で書かない。
- **source_name**: 発信元。法人格（株式会社など）は省く。
- **海外の記事**: **`quote`（原文からの一文引用）を付ける。** 英語のリリースから、核心を言っている一文（20〜45語）をそのまま写し、`quote: { text, source: "Samsung Newsroom" のような出典名, url: 原文の URL }` に入れる。言い換えない。**summary（ポイント3つ）は必須。** 英語のリリースを読まない読者のために、何が起きたか・金額や相手・今後の予定を日本語で3つに整理する（アプリでは加藤コメントの上に「ポイント」として出る）。title は日本語で、社名は原語のまま「米Teal Health、…」のように国を冠する。source_name は社名（英語のまま）。金額は「2,200万ドル（約35億円）」のように当日のおおよその相場で円換算を添える。summary・comment は日本語。コメントには、日本の読者にとっての含意（日本で同じことが起きるか、誰に影響するか）を1文入れる。
- **source_url**: PR TIMES の記事ページ URL（`https://prtimes.jp/main/html/rd/p/....html`）。
- **image_url**: `release.mjs` が返す og:image。無ければ上記3の方法で当事者（または官公庁）のロゴを入れる。
- **company**: 上記3の条件に合う会社。未上場は `name` / `profile`（設立年月、所在地、資本金、未上場、事業内容、許認可を1段落。代表者名は入れない）/ `url` / `ceo: { name, bio }`。上場企業は `name` / `listed` / `financials` / `profile`（1文）/ `url`。**`name` は記事の `source_name` と同じ表記にする**（企業ページで記事がまとまるように）。
- **published_date**: 今日の日付。
- **category**: 9つのどれか。
- **featured**: 上記3の判断で、直近24時間のトップにする場合だけ `true`（画像のある記事に限る）。それ以外は `false`。

### 5. 投稿
1. `pipeline/today.json` に書く（形は `pipeline/example.json`）。
2. `node pipeline/publish.mjs pipeline/today.json`（`data/articles.json` にマージされる）。
3. `pipeline/today.json` を削除する。
4. `node pipeline/substack.mjs` で Substack の投稿一覧も更新する（0本の回でもこれだけは行い、変更があれば push する）。
5. `git add data/ && git commit -m "配信 YYYY-MM-DD: N本" && git push origin main`
6. `https://raw.githubusercontent.com/hirokato-med/healthbiz-news/main/data/articles.json` を取得し、今日の記事が含まれていることを確認する（反映に数分かかることがある）。

### 6. 報告
最後に、配信した記事のタイトルと **コメント全文** を並べ、
そのあとに「見送った候補」として、その日に見た主なリリースの見出しと落とした理由を一行ずつ添える。
配信できなかった場合は理由を明記する。

## 重要な制約
事実を捏造しない。金額、社名、数字、設立年、資格は必ずリリース・会社概要・信頼できる記事から取る。
読んでいない記事の中身を推測で書かない。抽出がうまくいかず意味の通らない文字列になっている箇所は、そのまま引き写さずに落とす。
